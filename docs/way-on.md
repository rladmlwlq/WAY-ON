## 1. 한 줄 요약

동승자가 폰 지도에서 **지금 가는 경로 위의** 휴게소·충전소·맛집을 고르면, 운전자가 한 번 확인하고 Pleos 내장 내비의 경유지로 들어갑니다. 제출물은 차량 앱(APK)이고, 폰 웹과 서버가 이를 돕습니다.

## 3. 최종안

### 3.1 구성과 기술 스택

| 부분 | 기술 | 비고 |
|---|---|---|
| 차량 앱 `car-app/` | Kotlin 2.0.0, Compose(BOM 2024.04.01), AGP 8.8.2, compileSdk 35, minSdk 28, JDK 17 | `com.wayon.car`. Android Studio로 열기 |
| Pleos SDK | NaviHelper 3.0.5, Vehicle 2.3.2 | Vehicle은 배터리·연료(F6)와 기어로 정차 판단(3.8, 3.9). FusedLocation 1.1.3은 교체 대비로만 유지. TTS 3.3.1은 동승자 없을 때 음성 안내에 사용(3.11) |
| 차량 앱 통신 | Retrofit 2.11 + Gson, OkHttp 4.12 WebSocket | QR은 ZXing core 추가 제안 |
| 서버 `server/` | Java 21, Spring Boot 4.1.2, MyBatis 4.1.0, MySQL 8.4, Spring WebSocket(추가 필요) | IntelliJ로 열기 |
| 폰 웹 | React + Vite + TypeScript, 카카오맵 JS SDK, **Vercel** | 개발 `localhost:5173`, API·WS는 8080으로 프록시. 저장소에 아직 없음 |
| 실행 환경 | Pleos Connect Emulator 2.1.0 (API 34) | |
| 쓰지 않음 | Spring Security, Redis, Firebase | |

**외부 API는 모두 서버에서만 호출합니다.** 웹에 들어가는 키는 지도용 카카오 JS 키뿐입니다.

**Vercel 배포로 생기는 일**
- 웹과 서버 주소가 달라집니다. Spring에 CORS와 WebSocket 허용 Origin으로 웹 주소를 등록합니다.
- Vercel은 WebSocket 서버를 맡지 않습니다. 폰은 Spring 서버에 직접 WSS로 접속합니다. 서버 주소는 `VITE_API_URL`로 넣습니다.
- 인증은 쿠키 없이 지금 설계대로 토큰을 씁니다. REST는 헤더, WebSocket은 접속 후 첫 메시지입니다.
- QR 주소는 Vercel 주소입니다. 카카오 JS 키에도 이 주소를 등록합니다. 미리보기 배포는 주소가 바뀌니 운영 주소만 등록합니다.
- 새로고침해도 열리도록 모든 경로를 `index.html`로 보내는 설정을 넣습니다.
- 차량 앱은 영향이 없습니다. 서버 주소와 QR에 넣을 웹 주소만 설정값으로 둡니다.

### 3.2 연결과 화면

- 앱은 **보조 창**에서 내비와 나란히 실행하는 것을 기본으로 합니다. 화면 비율은 차종에 따라 1:1 또는 2:1입니다.
- Connect-W 차량은 조수석 쪽에서 앱을 실행하면 조수석 창에서만 실행됩니다. 동승자가 직접 QR을 띄우기에 좋습니다.
- **정차 중:** QR을 표시합니다. 일회용 코드, 만료 2분. 코드는 URL의 `#` 뒤에 넣습니다.
- **주행 중:** QR을 띄우지 않고 "정차 후 연결"만 안내합니다.
- **주행 중에 새 동승자가 연결하는 방법:** 자동 재연결된 동승자만 가능합니다. 4자리 코드가 허용되는지는 미확인입니다.
- 연결은 차량·폰 양쪽의 위치 공유 동의 후 완료됩니다.
- 앱은 운전 중 쓰려면 DO(Distraction Optimization)를 선언해야 합니다.
- 내비 위에 겹쳐 그리지 않습니다. 내비 화면 안에 넣는 API도 없습니다.

### 3.4 경로 위 장소 찾기 흐름

1. 차량 앱이 현재 위치(`getCurrentLocationInfo`)와 목적지를 WebSocket으로 서버에 보냅니다.
2. 서버가 카카오모빌리티 길찾기로 경로 좌표를 계산해 폰에 보냅니다. 경유지가 있으면 함께 넣습니다.
3. 칩을 누르면 서버가 차 앞쪽 경로 구간을 약 2km 간격으로 나눕니다.
4. 종류별로 다음 방식으로 찾습니다.

| 종류 | 방식 | 주의 |
|---|---|---|
| 휴게소 | `rest_area` DB와 경로 거리 계산 | 반대 차로 제외용 `travel_bearing`은 API에 없음 |
| 충전소 | 동기화한 DB와 경로 거리 계산 | 하루 1,000건. 상태는 `period=5`로 갱신 |
| 휴게소 맛집 | `rest_area`에 연결한 도로공사 메뉴·매장 DB | `stdRestCd`로 연결. 메뉴에 매장명은 없음(0502) |
| 휴게소 밖 맛집·카페·명소 | 카카오 로컬 카테고리 검색 | 좌표당 최대 45건. 앞쪽 구간만 검색. 휴게소 매장은 결과에서 제외 |
| 주유소 | 오피넷 `aroundAll` | **하루 300건**, 좌표는 KATEC, 서버 캐시 필수 |

5. 중복을 지우고, 몇 km 앞, 예상 시간, 경로에서 떨어진 거리를 붙여 보냅니다.
6. 차가 경로를 일정 거리 이상 벗어나면 다시 계산합니다. 경유지가 바뀌었을 때도 다시 계산합니다.
7. 길찾기가 실패하면 D5의 방향·목적지 근사로 대체합니다.

**한계:** 서버가 계산한 경로는 Pleos가 실제로 안내하는 경로와 다를 수 있습니다.

### 3.5 운전자 확인

처리 순서는 **서버 선점(ACCEPTED) → 내비 호출 → 결과 기록(APPLIED/FAILED)** 입니다 (D7).

| 순위 | 입력 | 상태 |
|---|---|---|
| 0 | Pleos 기본 확인 창 (휠·터치를 Pleos가 처리) | 있는지 미확인. 있으면 우리 수락 화면을 없앰 |
| 1 | 스티어링 휠 버튼 | 앱이 받을 수 있는지 미확인 |
| 2 | CCP 다이얼·물리 버튼 | 문서 있음 |
| 3 | 터치 [추가]/[거절] | 항상 제공 |
| 확장 | 음성 수락 (Gleo, STT) | SDK 미공개 또는 승인 필요 |

**확인 창이 있다고 확인되기 전에는 우리 수락 화면을 유지합니다.** 운전자 동의 없이 경로가 바뀌면 안 되기 때문입니다.

10초 동안 응답이 없으면 `EXPIRED`, 직접 거절하면 `REJECTED`입니다. 오류는 폰에만 표시합니다.

### 3.6 공영주차장 (N5)

1. 차량 앱이 `onDrivingInfo`로 목적지까지 남은 거리·시간을 봅니다. **남은 거리 10km 이내 또는 남은 시간 5분 이내**가 먼저 되는 시점에 서버에 요청합니다. 목적지가 바뀌기 전까지 1회만 보냅니다.
2. 서버가 목적지 반경 약 1km에서 찾습니다. 카카오 `PK6`으로 위치를 찾고, 공공데이터 주차장 정보로 공영 여부·요금을 붙입니다.
3. 폰에 공영이면서 가까운 순서로 보여 줍니다.
4. 운전자가 수락하면 **목적지를 주차장으로 바꿉니다**(`requestRoute`). 경유지로 넣으면 주차 후에도 원래 목적지로 계속 안내하기 때문입니다.

동승자가 없으면 음성으로 알리고(3.11), 목록은 정차 중 차량 화면에서 보여 줍니다.

### 3.7 주문 연결 (N7)

- 주문과 결제는 **동승자 폰에서만** 합니다. 차량 앱에는 넣지 않습니다.
- 휴게소를 고르면 메뉴(도로공사 0502)를 보여 주고, 땡겨요·네이버 주문 페이지로 연결합니다.
- 차량 앱이 아는 남은 시간으로 "도착 20분 전, 지금 주문하세요" 알림을 폰에 띄웁니다.
- 경유지가 빠지면 알림도 취소합니다.
- 공개 주문 API는 확인되지 않아, 직접 주문은 제휴가 필요한 확장 항목입니다.

### 3.8 휴게소 도착 안내 (A1)

`design.md`의 위치 판단 상태 머신과 진입 반경은 되살리지 않습니다. **경유지로 넣은 휴게소만** 안내하면 NaviHelper가 준 남은 거리로 판단할 수 있어서, 코드와 데이터가 크게 줄어듭니다. 배치도, 주차 위치 저장은 계속 뺍니다.

| 시점 | 판단 | 차량 화면 | 동승자 폰 |
|---|---|---|---|
| 접근 | `onDrivingInfo`의 경유지 남은 거리 2km 이하 | 한 줄: `곧 ○○휴게소` | 대표 메뉴, 지금 영업 중인 매장, 편의시설 |
| 도착 | 경유지 도착 또는 기어 P | 보조 창: 편의시설, 영업 매장, [출발 안내] | 같은 정보 + 주문 연결(N7) |
| 출발 | 기어 D | 기본 화면으로 복귀 | 안내 닫기 |

- 안내 정보는 N6의 DB에서 가져옵니다. 영업 중 여부는 매장의 `stime`~`etime`으로 계산합니다.
- 주행 중 차량 화면은 짧은 문구만 씁니다. 동승자가 없으면 접근 안내를 음성으로도 알립니다(3.11).
- 도착 판단에 쓸 NaviHelper 콜백은 시험이 필요합니다. 6장 참고.

### 3.9 출발 안내 (A2)

**검토 결과: 가능합니다. 다만 WebSocket만으로는 목적을 이루지 못합니다.** 이 기능이 필요한 순간은 동승자가 차 밖에 있고 폰이 잠겨 있을 때입니다. 이때 브라우저 페이지는 연결이 끊겨 있어서 메시지를 받지 못합니다. 그래서 **웹 푸시까지 있어야 제 역할을 합니다.**

| 단계 | 방식 | 받을 수 있는 경우 | 시기 |
|---|---|---|---|
| 1 | WebSocket + 화면 배너·소리 | 페이지가 열려 있을 때 | 11/15 |
| 2 | 웹 푸시 (Service Worker, VAPID) | 페이지가 닫혀 있거나 폰이 잠겨 있을 때 | PT 전 |

**웹 푸시 지원 범위**
- Android Chrome: 설치 없이 알림 허용만으로 동작합니다.
- iPhone: iOS 16.4 이상에서 **웹을 홈 화면에 추가해야** 동작합니다. 추가하지 않으면 페이지가 열려 있을 때만 받습니다.
- 문자·알림톡은 쓰지 않습니다. 전화번호를 모아야 하고 비용이 들기 때문입니다.

**동작**
1. 연결 후 폰에 "출발 알림 받기" 버튼을 둡니다. 브라우저가 사용자 동작 뒤에만 권한을 묻기 때문입니다.
2. 정차 중 차량 앱에 [출발 안내] 버튼을 표시합니다. 연결된 동승자가 있을 때만 보이고 주행 중에는 숨깁니다.
3. 버튼을 누르면 서버가 그 차량의 동승자 모두에게 보냅니다. WebSocket이 끊긴 사람에게는 푸시로 보냅니다.
4. 폰에서 알림을 확인하면 서버로 확인 메시지를 보냅니다. 차량 앱에 `2명 중 1명 확인`을 표시합니다.

**규칙**
- 보내는 권한은 **차량 토큰에만** 있습니다. 동승자는 보낼 수 없습니다.
- 문구는 고정값 "차량이 곧 출발합니다"입니다. 위치는 넣지 않습니다.
- 반복 전송을 막기 위해 30초에 1번만 보냅니다(제안).
- 동승자가 내려도 **차량 앱은 전송 실패를 운전자에게 경고로 띄우지 않습니다.** 확인 수만 보여 줍니다.

**세션 만료와의 충돌**

휴게소에서 시동을 끄면 차량 통신이 끊기고, 5분 무통신 규칙으로 세션이 만료됩니다. 돌아와서 버튼을 눌러도 받을 대상이 사라집니다. 그래서:
- 푸시 구독은 세션(`trip`)이 아니라 **등록 동승자(`passenger`)에 저장**합니다.
- 전송 대상은 "그 차량에 등록되고, 마지막 세션에 참여한 동승자"입니다.
- 따라서 A2의 2단계는 **자동 재연결(F5)의 `passenger` 구조가 필요합니다.**

### 3.10 에너지 제안 (F6)

잔량 %만 보면 목적지가 가까워도 알림이 뜨고, 멀어도 늦게 뜰 수 있습니다. 그래서 **남은 거리와 주행 가능 거리를 비교**합니다.

**판단:** `주행 가능 거리 < 목적지까지 남은 거리 + 여유 20km`(제안)

예: 목적지까지 50km 남았는데 주행 가능 거리가 60km면 제안합니다 (60 < 70).

| 값 | 출처 | 상태 |
|---|---|---|
| 목적지까지 남은 거리 | NaviHelper `onDrivingInfo` | SDK 소스로 확인 |
| 주행 가능 거리 | Vehicle SDK | Virtual Console에 항목 있음. SDK 속성은 미확인 |
| 도착 시 예상 배터리 (전기차) | NaviHelper `requestTrip()` → `onTripInfo` | SDK 소스로 확인. 충전소 경유 계획과 맞는지 시험 필요 |

**동작**
1. 차량 앱이 값을 비교합니다. 값이 바뀔 때만 다시 계산합니다.
2. 조건에 맞으면 동승자 폰에 알림을 띄웁니다. 예: `목적지까지 50km, 주행 가능 60km. 앞쪽 주유소를 확인하세요`
3. 경로 위 주유소를 보여 줍니다(전기차는 충전소). **주행 가능 거리 안에 있는 곳만** 표시합니다.
4. 고르면 일반 경유지 흐름(F3)과 같습니다.

**규칙**
- 목적지 1개당 1회만 보냅니다. 목적지가 바뀌거나 주행 가능 거리가 다시 늘면(주유 후) 초기화합니다.
- 목적지가 없으면 비교할 수 없어 보내지 않습니다. 이때는 차량 기본 경고에 맡깁니다.
- 동승자가 없으면 음성으로 알리고(3.11), 주유소 목록은 정차 중 차량 화면에서 보여 줍니다.
- 오피넷은 **하루 300건이고 반경이 최대 5km**입니다. 앞쪽 경로에서 몇 지점만 호출하고 캐시합니다.

### 3.11 음성 안내 (A3)

**검토 결과: 가능성이 높지만 시험이 필요합니다.** Pleos TextToSpeech SDK 3.3.1 사용 가이드가 있고 한국어(`ko-KR`)를 지원합니다. 다만 프로젝트·SDK 안내에는 TTS가 아직 "준비 중"이라 **사용 신청을 할 수 없습니다.** FusedLocation도 같은 상태인데 에뮬레이터에서는 동작했으므로, TTS도 시험해 봐야 합니다.

**"동승자 없음"의 기준:** 현재 세션에 연결된 폰이 0대일 때입니다. 실제로 사람이 타지 않았는지는 알 수 없습니다.

| 상황 | 시점 | 음성 문구 (예) | 이후 |
|---|---|---|---|
| 에너지 | 3.10 조건 충족 | "목적지까지 50킬로미터 남았는데 연료가 부족할 수 있어요. 주유소를 확인해 주세요." | 정차 중 차량 화면에 주유소 목록 |
| 공영주차장 | 3.6 조건 충족 | "목적지 근처 공영주차장을 찾았어요. 정차하면 화면에서 확인할 수 있어요." | 정차 중 차량 화면에 목록 |
| 휴게소 접근 | 3.8 조건 충족 | "곧 ○○휴게소에 도착해요." | 도착 시 차량 화면 |

**규칙**
- 각 안내는 조건마다 1회만 말합니다. 문구는 한 문장 안팎으로 짧게 합니다.
- 음성은 **알려 주기만** 합니다. 말로 경유지를 추가하려면 음성 인식(STT)이 필요해서 확장으로 둡니다.
- 동승자가 연결되어 있으면 음성 없이 폰으로 보냅니다.

**구현**
- `TextToSpeech(context, Mode.ON_DEVICE)`를 씁니다. 네트워크와 앱 등록(Client ID)이 필요 없습니다.
- 권한은 `pleos.car.permission.TTS_SERVICE`입니다. 초기화 후 `setLocale(Locale.KOREA)`, `speak()` 순서로 호출합니다.
- 내비 음성과 겹치지 않도록 재생 전에 오디오 포커스를 요청합니다. 포커스 변경 이벤트도 처리합니다. Pleos 정책입니다.
- 첫 음절이 잘리지 않도록 재생 앞에 150~200ms 묵음을 넣는 것이 권장 사항입니다.

**TTS를 쓸 수 없을 때:** 앱에 넣은 **녹음 음원**을 재생합니다. Pleos 가이드도 녹음 멘트를 음성 안내의 한 종류로 다룹니다. 다만 "50킬로미터" 같은 숫자는 빼고 고정 문구만 씁니다.

### 3.12 그대로 유지하는 규칙

- 세션은 통신 없이 5분이면 만료하고, 종료·만료 시 위치·목적지·에너지 값을 지웁니다.
- 토큰은 SHA-256 해시로 저장합니다. 차량 앱은 Android Keystore 등 보안 저장소를 씁니다.
- 대기 요청은 세션당 1건입니다. 새 요청이 오면 이전 요청은 `EXPIRED`가 됩니다.
- 서버는 1대로 운영합니다. WebSocket 세션은 서버 메모리에 둡니다.
- 오프라인 상태 UI와 재시도·타임아웃을 넣습니다. Pleos 정책 요구 사항입니다.
- 서버는 HTTPS/WSS(TLS 1.2 이상), IP 대신 도메인을 쓰고, 심사·전시 기간 상시 가동합니다.
- 협업은 `feature → main → develop`입니다. 테이블을 바꾸면 `erd.md`와 `schema.sql`을 같이 고칩니다.

### 8.4 확인하다 바뀐 사실

- **도로공사 데이터는 코드로 다 연결되지 않음.** 0501~0503은 `stdRestCd`로 연결되지만, 0504(주유소)는 주유소 코드라서, 판매순위 파일은 코드 체계가 달라서 **휴게소 이름으로** 연결해야 함. "주유소 코드 = 휴게소 코드 + 1"은 틀림 (164곳 중 60곳만 맞음)
- 0501 매장 데이터는 **프랜차이즈 브랜드만** 있음 (휴게소 자체 식당 없음)
- 0503에 화장실 항목은 없음
- 서울시 주차장은 노외 주차장 대부분이 좌표 없음, 총 주차면 1 이하인 더미 데이터 310곳
